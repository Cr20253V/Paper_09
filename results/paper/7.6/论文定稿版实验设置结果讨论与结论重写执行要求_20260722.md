## 一、任务定位与最终目标

本轮不是对现有第四至第六章进行局部润色，而是在不增加实验的前提下，对实验设置、结果与讨论、结论三个有效章节进行结构性重写，并完成与现有证据完全一致的图表配置。目标是把当前偏内部审计报告式的材料，整理为一篇逻辑完整、论证闭环、结论克制但贡献清晰的工程控制论文。

最终稿必须回答以下完整故事链：

1. 为什么当前 AGV 的 LPV-MPC 需要准确坡度调度；
2. 为什么仅依赖原始历史特征或简单因果 IMU 坡度不够；
3. 多尺度差分表示对坡度估计带来了什么可重复收益；
4. 因果惯性观测与 ModernTCN 在哪些区间具有互补性；
5. 有界、不确定度驱动的融合如何把互补信息传入控制器；
6. 这种改进实际改善了哪些闭环指标，哪些指标尚未获得一致支持；
7. 推理核心达到什么计算水平，完整控制链尚存什么工程边界；
8. 现有证据能够支持什么结论，不能支持什么结论。

全文叙事应形成如下闭环：

```mermaid
flowchart LR
    accTitle: 定稿章节的证据闭环
    accDescr: 从坡度调度价值出发，经估计、互补融合和闭环控制验证，最终回到受证据约束的结论。

    need["坡度调度是否必要"] --> estimate["能否因果估计坡度"]
    estimate --> delta["差分表示是否有效"]
    delta --> complement["IMU 是否提供互补信息"]
    complement --> fusion["有界融合是否改善调度坡度"]
    fusion --> control["收益是否传递到闭环控制"]

    compute --> boundary["结论范围与部署边界"]

    classDef question fill:#dbeafe,stroke:#2563eb,stroke-width:2px,color:#1e3a5f
```

最终稿不追求把所有实验结果写成正面，而要把最强证据放在主线上，把混合结果转化为机制解释和适用边界。所谓“扬长避短”只能表现为叙事重心、篇幅和顺序上的选择，不能删除会改变核心结论的负面或不确定结果。

### 5.3 节点 3：重写 Experimental Setup and Evaluation Protocol

建议结构如下：

#### 5.3.1 Research questions and evaluation logic

将当前四个问题调整为一条递进链，避免问题之间交叉：

- RQ1：准确坡度调度是否对当前 AGV-LPV-MPC 有价值；
- RQ2：Delta-bank 是否改善统一协议下的坡度估计，并能否传递到闭环；
- RQ3：合格因果惯性观测是否与 ModernTCN 互补，自适应融合是否有效；
- RQ4：五种坡度来源如何影响闭环跟踪、航向和输入增量；
- RQ5：核心推理与完整控制周期分别达到什么计算水平。

不得在实验设置中提前出现结果和结论。

#### 5.3.2 Simulation platform and frozen controller

只报告实际生效配置：MATLAB/Simulink 环境、对象版本、采样周期、`Np=150`、`Nc=30`、有效 Q/R/dR、约束和固定接口。不要把历史默认值或未生效配置写入正文。

#### 5.3.3 Data generation and dataset construction

按“路线模板—随机实现—输入与真值—窗口—划分—归一化—证据边界”顺序写：

- 51 个路径模板、每模板 2 次随机实现，共 102 个连续 run；
- 22 维因果输入不含真实坡度和直接坡度/俯仰测量；
- 128 步历史窗口，主方法扩展为 88 维；
- train/validation/test 按 run 隔离；
- 归一化只由训练集拟合；
- 28 个模板的两次实现跨不同集合，因此不是严格模板隔离；
- 离线测试用于同协议内部算法比较，不承担未知几何或实车泛化证明。

#### 5.3.4 Compared estimators and grade sources

拆成两个层次：

- 估计器比较：ModernTCN-delta、ModernTCN-22D、GRU-22D、TCN-22D；
- 控制器坡度源比较：zero grade、simple causal IMU、ModernTCN、Fusion、truth-driven conditioned reference。

必须说明所有控制器共享同一对象、控制器结构、权重和约束。该设计隔离的是坡度源影响，不等价于对每个坡度源分别最优整定后的控制器比较。

#### 5.3.5 Routes, seeds, and statistical units

明确：

- 六条闭环路线的物理角色；
- 十个模型种子；
- 确定性坡度源每路线一个 case；
- 学习坡度源每路线十个模型种子；
- 同时报告 route-level 与 route–seed-level 结果；
- 代表曲线固定采用预先确定的路线和 seed 42，不因指标改变而更换。

不要把 60 个 route–seed case 简单写成 60 个完全独立道路实验。

#### 5.3.6 Metrics and statistical analysis

区分四类指标：

- 坡度估计：MAE、P95、必要时边界误差；
- 闭环跟踪：`e_y` RMS、`e_psi` RMS、position RMS；
- 控制行为：`J_{Delta u}`、yaw-rate command RMS；
- 工程执行：求解失败、约束记录、超时、核心推理时延和完整周期时延。

说明低值为优、初始化排除、配对方式、置信区间方法和实际统计单位。将安全记录与性能优势分开，不能用“没有记录到失败”代替性能证据。

#### 5.3.7 Reproducibility and protocol lock

报告冻结数据、路径、种子、控制器和后端，说明图表从正式结果只读生成。避免堆叠内部 Node 编号和目录历史；只在 Data/Code Availability 或补充材料追溯表保留完整路径。

### 5.4 节点 4：重写 Results and Discussion

结果部分按科学问题而不是 Node36–42、A1–A5 的项目节点组织。建议最终结构如下。

#### 5.4.1 Accurate grade information establishes the control opportunity

目的：先证明坡度信息对当前控制链确实重要，为后续估计与融合提供必要性。

写作顺序：

1. 给出 truth-driven conditioned reference 与 zero-grade 的主要配对效应；
2. 说明 simple causal IMU 相对 zero-grade 结果混合；
3. 得出“准确坡度有价值，但不准确坡度并不自动产生控制收益”；
4. 引出对可靠估计和条件化接口的需要。

不得把 truth-driven reference 写成可部署方法，也不得由其上界结果推出任意估计器有效。

#### 5.4.2 Delta-bank improves offline grade estimation

这是全文最强结果之一，应给予充分篇幅：

1. 报告四种估计器统一十种子离线结果；
2. 给出 ModernTCN-delta 相对三个基线的配对效应和置信区间；
3. 单独解释 delta-bank 相对 ModernTCN-22D 的表示贡献；
4. 明确这是 run-disjoint、非 template-disjoint 的同域内部比较。

不要用辅助分类准确率替代坡度误差主结论，也不写“ModernTCN 普遍优于所有时序网络”。

#### 5.4.3 Offline gains translate selectively to closed-loop behavior

目的：主动处理离线优势未完全转化为闭环优势的问题。

必须先给总体判断：离线优势没有在所有闭环指标上形成统一额外改善。随后报告相对 GRU/TCN 的支持结果，以及相对 ModernTCN-22D 时 `J_{Delta u}` 更明确、跟踪误差区间跨零的事实。

四个种子触发冻结门限的事实应压缩为一个边界段落，说明它们来自种子级离线资格检查在六条路线上的重复映射，而不是 24 次独立闭环失稳。

#### 5.4.4 Causal inertial observation provides conditional complementarity

先报告合格惯性观测器的 90-case 资格结果，再用预定整路线曲线展示：

- IMU 误差低于 ModernTCN 的区间；
- IMU 无效或不利的区间；
- 有效性和融合增益状态；
- 为什么不能使用固定替换或固定权重。

Node36–38 的开发历史最多压缩为一段方法动机，不逐个报告内部门限。

#### 5.4.5 Adaptive fusion improves mean grade accuracy but remains case-dependent

先用三路线三种子 pilot 说明固定修正与自适应修正的区别，再给九路线十种子的 90-case 结果。正文应写：平均坡度误差和综合控制比改善得到支持，但严格逐例一致性门限未满足。

不得把这 90 个开发 case 称为独立确认集。若保留 `J_ctrl`，必须给出其组成和方向；若与主要闭环指标解释重复，可将其降为开发指标并把主要控制结论交给五控制器比较。

#### 5.4.6 Five-source comparison defines the end-to-end effect

这一节作为完整方法的闭环落点：

1. 先给五种坡度源的原始均值和统计单位；
2. 再聚焦 Fusion 与 MTCN 的 60 个配对 case；
3. 明确调度坡度 MAE 和航向误差的改善获得支持；
4. 明确横向误差和 `J_{Delta u}` 的区间跨零；
5. 通过路线分层解释收益为何不一致。

不得在表格中用粗体把 Fusion 的所有均值暗示为统计显著最优。粗体只用于得到预定义统计支持的比较，或完全取消粗体。

#### 5.4.7 Route and seed effects explain the mixed aggregate response

将当前 Hierarchical Effects 和 Failure Cases 合并为紧凑的机制讨论：

- 工厂物流和急转衔接路线表现；
- 长上下坡和下坡恢复路线的权衡；
- 平缓路线的有限变化；
- 最不利路线—种子组合；
- 结果对路线几何和初始化的依赖。

这一节不得临时寻找新的“最好案例”。所有定性案例必须来自预先指定集合，图中保留完整路线和局部退化区间。

#### 5.4.8 Core inference is fast, whereas the full MATLAB cycle is not yet real time

同时给出：

- 参数量和 ONNX 文件大小；
- 同后端、单线程、批量 1 的 p50/p95/p99；
- 超过 10 ms 的调用数；
- 完整 MATLAB 周期 P95 约 52.21 ms。

结论仅为“核心网络推理具有实时潜力”。不得把输入构造、观测器、融合、Simulink 传输和 MPC 求解排除后的计时写成完整部署时间。

#### 5.4.9 Integrated interpretation and limitations

讨论必须完成四件事：

1. 解释准确坡度、估计误差、调度接口和闭环指标之间的因果链；
2. 与本地参考论文比较写作逻辑和工程取舍；
3. 区分明确支持、部分支持和未确认结果；
4. 集中陈述仿真域、划分、同域 Fusion 开发、复合输入增量和完整周期限制。

避免把内部审计状态表原样搬进讨论。可用一张简洁的“研究问题—主要发现—边界”总结表，但正文必须以完整段落解释，不能依赖表格代替论证。

### 5.5 节点 5：新写 Conclusion

新 Conclusion 建议为 3 至 4 个完整段落，不使用项目节点名，不重复全部表格数字。

段落结构：

1. 研究对象与方法链：22 维动力学输入、delta-bank ModernTCN、合格因果惯性观测、有界融合和坡度调度 LPV-MPC；
2. 明确支持的发现：准确坡度价值、离线坡度估计改善、融合平均坡度收益；
3. 条件性发现：闭环收益主要出现在航向误差及部分输入增量表现，横向误差和其他指标未形成统一额外优势；
4. 证据边界：同域仿真、非模板隔离、无实车/HIL、完整 MATLAB 周期未达 100 Hz、未提供形式化稳定性证明。

| 证据情况 | 推荐动词 | 避免动词 |
| --- | --- | --- |
| CI 和预定义比较支持 | reduced、improved、demonstrated within the tested domain | proved universally、guaranteed |
| 均值有利但 CI 跨零 | showed a favorable mean trend、was not statistically resolved | improved significantly |
| 开发集或机制证据 | indicated、suggested、provided same-domain evidence | validated independently |
| 未执行验证 | remains to be evaluated | is robust、is deployment-ready |

## 十二、未修改部分的后续同步清单（不属于本轮执行计划）

本节只记录本轮完成后，论文未修改部分需要根据新实验、结果和结论进行的措辞或内容同步。新对话执行本轮计划时不得把这些事项自动纳入修改范围。

### 12.1 标题

- 检查标题是否包含 `robust`、`real-time`、`stable` 或等价强词。
- 如果存在，应改为突出 history-based grade estimation、bounded inertial correction、grade-conditioned LPV-MPC 和 dual-drive-and-steer AGV。
- 标题不应暗示实车验证、全链 100 Hz 或所有控制指标全面提升。

### 12.2 摘要

- 将稳定性、鲁棒性、轻量化完整计算和部署就绪等过强结论降级。
- 明确研究为 simulation-based evaluation。
- 摘要只选 2 至 4 个最重要数字，优先离线 MAE、受支持闭环指标和 ONNX 核心 P95。

- Fusion 只能写 selected closed-loop metrics 或 heading-error improvement，不能写 comprehensive improvement。
- 不得把 Node42 的同域开发结果写成 independent validation。

### 12.3 Introduction 的研究空白与动机

- 研究空白应从“准确坡度对调度控制有价值，但单一来源存在误差和工况依赖”展开。
- 避免预设“融合必然提高所有闭环指标”。
- 增加离线估计精度不一定转化为闭环收益这一控制接口问题，作为本文系统评价的必要性。
- 文献对照应覆盖估计、信息融合、坡度调度控制和性能—计算权衡，而不是只比较网络结构。

### 12.4 Contributions

- 贡献 1：22D 因果动力学输入和 delta-bank 表示，限定为统一协议下的离线改善。
- 贡献 2：合格因果惯性观测、有界不确定度融合和精确回退，限定为同域平均收益。
- 贡献 3：融合坡度进入 LPV-MPC 的连续调度接口及五坡度源系统评价，明确闭环收益具有指标依赖性。
- 贡献 4 如包含实时性，只能称 core-inference feasibility，不写 full-stack real-time implementation。
- 不使用 universally superior、guaranteed stable、robust under arbitrary disturbances 等措辞。

### 12.6 第二章 AGV Modeling and Problem Formulation
